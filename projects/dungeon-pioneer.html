PROJECT OVERVIEW

빛이 곧 길이 되는 던전 탐험

던전 개척자의 던전은 기본적으로 어둡습니다. 플레이어는 벽에 횃불을 걸어 길을 밝히고, 밝힌 곳만큼 지도가 채워지며 던전을 “개척”합니다. 하지만 횃불에는 수명이 있고, 적은 플레이어뿐 아니라 횃불을 노리고 꺼뜨립니다. 빛이 탐색 자원이자 전투의 대상이 되는 구조입니다.

3인 팀(개발 · 기획 · 아트)에서 메인 개발을 맡아 횃불 · 적 AI · 던전 · 미니맵 · 전투 · UI를 구현하고 있습니다. 또 맵을 만드는 기획 · 아트 팀원이 코드 없이 던전 · 필드 · 마을 맵을 만들 수 있도록 맵 빌더 에디터 툴을 직접 만들어 제공했습니다. 현재 개발이 진행 중인 프로젝트입니다.

THE GAME

횃불을 걸고, 지도를 채우고, 빛을 지킨다

오버월드에서 던전 입구로 들어가면, 손에 든 횃불이 닿는 곳만 보이는 어두운 던전이 시작됩니다. 벽에 횃불을 걸어 길을 밝히고, 계단을 따라 층을 내려가며 적과 함정을 넘어 던전을 개척합니다.

DARK

어둠이 기본

던전은 플레이어 주변만 보입니다. 앞을 보려면 빛이 필요하고, 빛이 닿지 않은 곳은 지도에도 남지 않습니다.

TORCH

횃불이 길이 된다

벽의 원하는 면에 횃불을 걸어 길을 밝힙니다. 횃불이 비춘 곳은 탐색한 곳으로 지도에 영구히 기록됩니다.

ENEMY

빛을 노리는 적

적은 시야 안에 들어온 플레이어를 쫓고, 근처의 횃불을 때려 꺼뜨립니다. 수명이 깎인 횃불은 결국 사라집니다.

EXPLORE

개척도

미니맵에 지금까지 밝힌 바닥의 비율이 표시됩니다. 던전을 얼마나 개척했는지가 진행의 지표가 됩니다.

ENGINEERING NOTES

구현 사례

01

수명이 있는 횃불과 적의 소등

탐색에 쓰는 빛이 설치 위치와 시간, 적의 공격에 따라 달라지도록 벽 면 단위 설치와 수명 게이지를 구현했습니다.

설치
  • 벽 면 단위 — 벽 콜라이더의 6방향 면 중 하나(faceKey)에 횃불을 붙임. 같은 면에는 중복 설치 불가, 다른 면에는 설치 가능
  • 설치 · 복원 규칙 공유 — 위치 · 회전 계산(GetMountPose)을 설치와 복원이 같은 함수로 사용 → 던전을 나갔다 와도 같은 자리에 복원
  • 함정 벽 — 함정이 숨은 벽에 설치를 시도하면 횃불 대신 함정이 발동
수명과 소등
  • 수명 게이지 — 기본 180초, 남은 비율을 게이지로 표시. 마지막 10초 동안 밝기 · 범위가 줄어듦 (범위는 최소 30% 유지)
  • 적의 공격 — 피해량과 무관하게 한 대에 60초 감소 → 세 번 맞으면 소멸
  • 누적값 없는 밝기 — 밝기를 매 프레임 남은 시간에서 계산해, 층을 다시 켜거나 복원한 첫 프레임부터 정확
  • 광원 · 미니맵 · AI 연결 — 켜진 횃불만 정적 집합으로 관리하고, 미니맵 광원과 적 AI가 같은 목록을 사용
한 대에 60초를 깎고, 밝기는 남은 시간에서 파생 TorchInstance.cs
public void TakeDamage(float damage, Transform attacker)
{
    if (!IsAlive || damage <= 0f) return;

    expiresAt -= secondsPerHit;   // 피해량과 무관하게 한 대 = 60초
    ApplyFade();                  // 게이지 · 밝기에 바로 반영
}

private void ApplyFade()
{
    float t = fadeOutSeconds > 0f ? Mathf.Clamp01(Remaining / fadeOutSeconds) : 1f;
    torchLight.intensity = baseIntensity * t;
    torchLight.range     = baseRange * Mathf.Lerp(minRangeRatio, 1f, t);   // 불씨처럼 최소 범위 유지
}

// 설치와 복원이 같은 규칙을 써야 복원된 횃불이 처음 자리에 그대로 나온다
public static void GetMountPose(Collider wallCollider, Vector3Int faceKey, out Vector3 position, out Quaternion rotation)
{
    Vector3 normal = faceKey;
    Bounds bounds = wallCollider.bounds;
    position = bounds.center + Vector3.Scale(normal, bounds.extents);
    rotation = Quaternion.LookRotation(normal);
}

02

LocationGrid 기반 적 AI — 순찰, 시야, 그리고 횃불 사냥

타일 단위로 바뀌는 던전 구조에 맞춰 NavMesh에서 LocationGrid A* 기반 이동으로 전환하고, FOV 감지와 횃불 사냥을 연결했습니다.

이동 — Grid A*
  • LocationGrid — 층마다 바닥 · 벽 · 함정 구덩이 · 밀 수 있는 블록 같은 셀 정보를 만들고, 지형 · AI · 미니맵이 함께 사용
  • 전환 이유 — 블록이 칸을 막거나 구덩이가 메워지는 등 칸 단위로 바뀌는 통행 정보를 그대로 경로 탐색에 쓰기 위해
  • GridMover — A* 경로를 따라가며 앞 6칸까지 직선으로 갈 수 있는지 검사해 모서리를 깎아 이동
  • 재탐색 — 대상의 칸이 바뀌거나 0.5초마다, 또는 0.5초 이상 제자리면 경로 재계산
  • GridSearch — 범위 탐색(BFS) 버퍼를 재사용해 반복 할당 감소
감지 — FOV
  • 전방 시야 120° — 탐지 반경 + 벽에 막히지 않은 시야선이 있어야 발견
  • 시야 밖 감지 — FOV 밖에서 달려 접근하면 1/3 반경 안에서 반응해 경계(Alert) 상태로
  • 추격 유지 — 추격 중에는 FOV와 무관하게 반경의 1.5배까지 대상을 유지
  • 후방 공격 — FOV 밖에서 맞으면 받는 피해 1.5배
  • 적 FSM — Idle · Patrol · Alert · Chase · Attack · Hit · Dead 7개 상태가 같은 감지 · 이동 함수를 공유

횃불 사냥 — 적은 플레이어를 찾지 못했을 때 시야 안에 들어온 횃불 중 앞 바닥 셀에 설 수 있는 가장 가까운 횃불을 목표로 삼아 공격합니다. 걸어가는 동안 모퉁이에 가려지는 건 정상이므로 시야 대신 “갈 수 없게 됐는지”와 “도착했는데도 못 때리는지”만 보고, 3초 동안 공격하지 못하면 포기한 뒤 그 횃불을 10초 동안 무시해 닿을 수 없는 횃불 앞에서 맴도는 상황을 막았습니다. 횃불을 노리던 중에도 플레이어를 발견하면 대상을 플레이어로 바꿉니다.

시야 · 거리 · 접근 셀 · 포기 목록을 통과한 가장 가까운 횃불 EnemyController.cs
foreach (TorchInstance torch in TorchInstance.EnumerateActiveTorches())
{
    if (torch == null || !torch.IsAlive) continue;
    if (IsTargetIgnored(torch)) continue;                       // 최근에 포기한 횃불

    float distance = GetHorizontalDistanceTo(torch.transform.position);
    if (distance > detectionRadius || distance >= nearestDistance) continue;
    if (!IsInFieldOfView(torch.transform.position)) continue;
    if (!Grid.IsPassable(torch.ApproachCell, false)) continue;  // 횃불 앞 칸에 설 수 있어야 함
    if (!CanSeeTarget(torch)) continue;                         // 벽에서 살짝 띄운 AimPoint로 시야선 검사

    nearestDistance = distance;
    nearest = torch;
}
LocationGrid→A* 경로 탐색→FOV · 순찰→격자 기반 이동

03

기획 · 아트 팀원을 위한 맵 빌더 에디터 툴

기획 · 아트 팀원이 코드 없이 던전 · 필드 · 마을 맵을 만들 수 있도록, 팔레트 기반 배치와 맵 굽기를 제공하는 에디터 툴을 직접 만들어 제공했습니다.

문제

여러 던전 · 필드 · 마을의 타일과 환경 배치를 반복해서 만들어야 했고, 맵을 직접 만드는 사람은 프로그래머가 아닌 기획 · 아트 팀원이었습니다. 프리팹을 하나씩 씬에 놓고 좌표 · 회전 · 부모를 맞추는 방식으로는 제작이 느리고, 게임 코드가 기대하는 구조(그리드 원점, 종류별 묶음, 씬 설정 컴포넌트)를 사람이 매번 지켜야 했습니다.

해결 — 배치
  • 맵 종류 탭 — 던전 · 필드 · 마을 탭마다 쓸 수 있는 팔레트 타입만 허용하고, 쓸 수 없는 타입은 경고
  • 팔레트 파일 — 팔레트를 ScriptableObject 에셋으로 저장해 Git으로 공유, 프리팹을 칸에 끌어다 놓으면 바로 추가
  • 브러시 — Shift+클릭 · 드래그 칠하기, Shift+우클릭 지우기, Ctrl+휠 브러시 크기, 설치 높이(층) 지정
  • 고스트 미리보기 · 안내판 — 놓기 전 반투명 미리보기, 씬 뷰 왼쪽 위에 현재 팔레트 · 높이 · 브러시 · 회전 표시
  • Undo 한 단계 — 한 번의 붓질을 Undo 그룹 하나로 묶어 Ctrl+Z 한 번에 되돌림

굽기 · 협업 안전장치

기능동작막는 문제
맵 굽기작업 컨테이너를 프리팹으로 저장. 필드 · 마을은 루트에 SceneLocation, 장애물 묶음에 GridBlocker 자동 부착구운 맵이 LocationGrid · NPC 이동에 반영되지 않는 문제
불러오기기존 맵 프리팹을 풀어 다시 편집, 맵 종류 탭을 자동 전환하고 오브젝트를 종류별 묶음으로 정리필드 맵을 던전 탭으로 구워 씬 설정이 떨어지는 실수
덮어쓰기 경고같은 이름의 맵이 있으면 “다른 팀원의 직접 수정이 사라진다”는 확인창최신 버전을 불러오지 않고 덮어쓰는 협업 충돌
참조 보존덮어써도 프리팹 루트 오브젝트 ID를 되돌림던전 씬이 들고 있는 맵 참조가 끊기는 문제
실수 방지Prefab Variant 맵 불러오기 차단 · 필드 바닥이 (0,0) 칸에서 시작하지 않으면 경고Variant 재저장 반복, 음수 칸 바닥이 그리드에서 빠지는 문제
덮어써도 던전 씬의 맵 참조가 끊기지 않도록 루트 ID 보존 MapBuilderEditor.cs

04

빛과 탐색 상태를 반영하는 미니맵

어둠 속 미탐색 영역과 광원으로 보이는 영역을 구분해 그리고, 변화한 범위만 다시 칠해 전체 갱신 비용을 피했습니다.

던전 미니맵
  • 픽셀 단위 시야선 — 미니맵 픽셀마다 광원에서 격자를 따라가며(DDA) 벽 · 블록에 가려지는지 계산
  • 밝기표 — 거리² 기준 256칸 감쇠표로 밝기를 조회해 매번 거리 계산을 하지 않음
  • 탐색 기록 — 빛이 닿은 바닥은 탐색한 곳으로 영구 기록, 탐색 비율을 개척도로 표시. 꺼진 횃불의 빛은 빠져도 기록은 남음
  • 부분 갱신 — 이전 밝힌 범위와 새 범위의 합집합만 다시 칠함
  • 층별 기록 — 층을 떠날 때 탐색 기록을 저장했다가 다시 들어오면 복원
광원 범위 안 픽셀만 순회해 밝기표에서 조회 MinimapVisionMap.cs
for (int y = y0; y <= y1; y++)
for (int x = x0; x <= x1; x++)
{
    int i = y * Width + x;
    if (kinds[i] == PixelKind.Solid) continue;

    float px = (x + 0.5f) * inv, py = (y + 0.5f) * inv;
    float dx = px - center.x, dy = py - center.y;
    float distanceSq = dx * dx + dy * dy;
    if (distanceSq > radiusSq) continue;

    bool endBlocked = IsBlocking(x / pixelsPerTile, y / pixelsPerTile);
    if (!CanSee(center.x, center.y, px, py, endBlocked)) continue;  // 격자 DDA 시야선

    byte light = falloff[(int)(distanceSq * toFalloffIndex)];       // 256칸 밝기표
    if (light > mask[i]) mask[i] = light;                            // 겹치면 밝은 쪽
}
