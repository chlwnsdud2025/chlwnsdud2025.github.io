PROJECT OVERVIEW

겨울 오두막의, 손에 닿는 상호작용

VR의 재미는 버튼 대신 내 손으로 직접 물건을 다루는 데 있습니다. 그런데 손으로 던진 다트는 물리 엔진이 따라잡지 못할 만큼 빠르고, 허공에 그린 그림은 사람마다 시작점과 방향이 제각각입니다. Winter Stove에서는 이런 “손동작의 오차”를 흡수해, 플레이어가 의도한 대로 판정되는 상호작용을 만드는 데 집중했습니다.

3인 팀이 약 2.5주 동안 Meta Quest용으로 개발했습니다. 저는 다트 · 화이트보드 · 젠가 · 설거지 등 VR 상호작용 오브젝트 11종, 화이트보드의 그림 제스처 인식, 그리고 쓰다듬고 안아 들 수 있는 고양이 AI를 구현했습니다.

내가 맡은 일

  • 다트 — 고속 투척 관통을 막는 자체 CCD (속도 기반 Raycast 선판정 · 위치 보정 · 1cm 중앙 판정)
  • 화이트보드 — VR 드로잉 입력과 $1 Unistroke Recognizer 확장
  • 고양이 — 8개 State FSM + NavMesh, XR Hover / Select 이벤트 반응
  • 상호작용 오브젝트 — 젠가 · 카드 · 설거지 · 술 · TV · 쓰레기 · 샌드백 · 총

THE GAME

난로 곁에서 손으로 노는 시간

플레이어는 난로가 있는 겨울 오두막 안에서 손에 닿는 물건으로 자유롭게 놀며 쉽니다. 퀘스트 패널에는 “다트 중앙 맞추기”, “삼각형 그리기”, “샌드백 1000점” 같은 도전 과제가 있고, 오브젝트를 직접 다루며 하나씩 달성합니다.

GRAB

잡고

젠가 블록을 조심스럽게 빼고, 카드를 섞어 나눠 주고, 접시를 닦아 건조대에 정리합니다.

THROW

던지고

다트를 과녁에, 쓰레기를 휴지통에 던집니다. 던진 속도와 방향이 그대로 결과가 됩니다.

TILT

기울이고

병을 기울여 술을 따르고 잔을 입가로 가져가 마십니다. 세 잔을 마시면 화면이 일렁입니다.

DRAW

그리고, 쓰다듬고

화이트보드에 도형을 그리고, 오두막을 돌아다니는 고양이를 쓰다듬거나 안아 올립니다.

ENGINEERING NOTES

구현 사례

01

다트 — 고속 투척 관통을 막는 자체 CCD

빠르게 던진 다트가 물리 스텝 사이에 과녁을 지나치던 문제를, 다음 이동 구간을 미리 Raycast로 검사해 해결했습니다.

문제

VR에서 손으로 던진 다트는 한 번의 FixedUpdate 동안 이동하는 거리가 과녁 두께보다 커서, 두 물리 스텝 사이에 과녁을 지나쳐 충돌이 누락되었습니다. 플레이어 입장에선 분명 맞혔는데 다트가 벽에 박히거나 바닥에 떨어지는 상황입니다.

해결
  • 이동 구간 선검사 — 매 FixedUpdate마다 다트 끝(dartTip)에서 진행 방향으로 속도 × fixedDeltaTime + 여유 거리만큼 Raycast
  • 꽂힌 위치 보정 — 맞으면 hit.point − dartTip.position만큼 다트를 옮겨 끝을 표면에 맞춘 뒤 Kinematic으로 고정
  • 비행 자세 보정 — 비행 중 forward를 속도 방향에 맞춤
  • 중앙 판정 — 고정 직후 다트 끝 반경 1cm OverlapSphere로 중앙 영역 검사
다음 물리 스텝에 이동할 구간을 미리 검사 DartBehavior.cs
void FixedUpdate()
{
    if (isFlying && !isStuck)
    {
        Vector3 rayOrigin = dartTip.position;
        float rayDistance = rb.linearVelocity.magnitude * Time.fixedDeltaTime + raycastrength;

        if (Physics.Raycast(rayOrigin, transform.forward, out RaycastHit hit, rayDistance))
        {
            if (hit.collider.CompareTag("DartBoard") || hit.collider.CompareTag("DartMiddle"))
            {
                transform.position += (hit.point - dartTip.position);  // 다트 끝을 과녁 표면에 맞춤
                StickToBoard();                                         // Kinematic 고정 → 중앙 판정
                return;
            }
        }

        if (rb.linearVelocity.sqrMagnitude > 0.1f)
            transform.forward = rb.linearVelocity.normalized;      // 비행 자세 보정
    }
}
결과
  • 판정 — 빠르게 던져도 과녁을 통과하지 않고, 다트 끝이 실제로 닿은 위치에 꽂힘
  • 정확도 — 위치를 보정한 뒤 중앙 판정을 하므로, 다트 끝이 중앙 영역에 닿았는지를 그대로 판정
  • 상호작용 — XRGrabInteractable의 놓기(selectExited)로 비행을 시작하고, 꽂힌 다트를 다시 잡으면(selectEntered) 상태를 초기화
관련 코드DartBehavior.cs
02

화이트보드 — 시작점과 방향에 흔들리지 않는 $1 Recognizer

펜으로 그린 궤적을 2D 점열로 바꾸고, 어느 꼭짓점에서 시작하든 어느 방향으로 그리든 같은 도형으로 인식하도록 $1 알고리즘을 확장했습니다.

VR 드로잉 입력

PEN TIP

펜촉 판정

펜촉 10cm 뒤에서 보드 방향으로 Raycast. 손에 물리 저항이 없는 VR에서 펜촉이 보드를 파고들어도 표면을 놓치지 않습니다.

STROKE

선 그리기

펜촉이 보드에 가까워지면 획을 시작하고, 5mm 이상 움직일 때만 LineRenderer에 점을 추가합니다.

2D

획 종료 · 2D 변환

펜을 떼면 한 획 종료. 점 10개 이하는 노이즈로 무시하고, 펜 기준 로컬 좌표로 바꿔 깊이(Z)를 버린 2D 점열을 인식기에 넘깁니다.

문제

원본 $1 알고리즘은 첫 점을 기준으로 회전을 정규화하고 점을 순서대로 비교합니다. 그래서 같은 삼각형이라도 다른 꼭짓점에서 시작하거나 반대 방향으로 그리면 점 순서가 템플릿과 어긋나 점수가 크게 떨어졌습니다.

인식 파이프라인

  1. Resample — 획 전체 길이를 63등분해 입력 길이와 상관없이 점 64개로 통일
  2. 후보 생성 — 점열을 0 · 8 · 16 … 56칸 순환(시작점 8개) × 정방향 / 역방향 = 후보 16개
  3. 정규화 — 각 후보를 RotateToZero(첫 점 각도 0°) → 250 × 250 영역으로 ScaleToSquare → 중심을 원점으로 이동
  4. 회전 탐색 — 템플릿과 ±45° 범위에서 황금분할 탐색(2° 정밀도)으로 점 사이 평균 거리가 최소인 각도 탐색
  5. 점수화 — score = 1 − 최소 평균 거리 / (½ × 250√2) → 씬에 설정한 기준 0.92 이상이면 성공
시작점 8개 × 정 / 역방향 후보 비교 DollarRecognizer.cs
for (int step = 0; step < targetPointCount; step += shiftStep)  // 0, 8 … 56
{
    List<Point> shiftedForward = ShiftArray(forwardPoints, step);
    shiftedForward = RotateToZero(shiftedForward);
    shiftedForward = ScaleToSquare(shiftedForward, boxSize);
    shiftedForward = TranslateToOrigin(shiftedForward);
    // 역방향도 같은 과정 (생략)

    for (int i = 0; i < templates.Count; i++)
    {
        float dF = DistanceAtBestAngle(shiftedForward,  templates[i], -45f, 45f, 2f);
        float dB = DistanceAtBestAngle(shiftedBackward, templates[i], -45f, 45f, 2f);
        float minDistance = Mathf.Min(dF, dB);
        if (minDistance < bestDistance)
        {
            bestDistance = minDistance;
            bestTemplateIndex = i;
        }
    }
}

// 0~1 점수 (1에 가까울수록 일치)
float halfDiagonal = 0.5f * Mathf.Sqrt(boxSize * boxSize + boxSize * boxSize);
float score = 1f - (bestDistance / halfDiagonal);
결과
  • 입력 자유도 — 어느 꼭짓점에서 시작하든, 어느 방향으로 그리든 삼각형 템플릿 1개로 판정
  • 판정 기준 — 영상의 예시 입력 기준 삼각형 93.7% · 원 81.5%로, 0.92 기준에서 두 도형을 구분 (설명용 입력을 실제 판정 코드로 계산한 값이며 인식률 통계가 아닙니다)
  • 연결 — 성공하면 이벤트 채널로 알리고 “삼각형을 그리세요!” 퀘스트 조건을 달성 처리 · 리셋 버튼으로 보드의 선 전체 삭제

03

고양이 — 스스로 노는 FSM, 손에는 즉시 반응

자율 행동은 상태 클래스로 나누고, 쓰다듬기 · 들기 같은 손 입력은 XR 이벤트로 어느 상태에서든 즉시 전환되도록 만들었습니다.

설계
  • 상태 클래스 분리 — CatBaseState(Enter · Update · Exit)를 상속한 8개 State. 전환은 항상 Exit → Enter 순서
  • 확률 기반 자율 행동 — Idle 1초 후 Walk 40% · Run 20% · Stretch 20% · Sleep 10% · 대기 연장 10%. 목적지는 NavMesh.SamplePosition으로 이동 가능한 지점만
  • XR 이벤트 전환 — Hover Entered → Petted, Select Entered → Grabbed(NavMeshAgent 비활성화), Select Exited → PutDown → Idle
  • 애니메이션 종료 판정 — normalizedTime과 IsInTransition을 함께 확인. 수면은 눕기 → 15~30초 수면 → 기상 3단계
  • 상태 기억 — 잡히기 직전 수면 여부를 기억해 들어 올림 · 내려놓기 모션을 다르게 재생
XR Interactable 이벤트에 연결된 진입점 CatController.cs
public void OnHoverEntered()          // 손이 닿으면 애교
{
    if (stateMachine.CurrentState != grabbedState)
        stateMachine.ChangeState(pettedState);
}

public void OnGrabEntered()           // 들어 올리면, 자던 중이었는지 기억
{
    wasSleepingBeforeGrab = (stateMachine.CurrentState == sleepState);
    stateMachine.ChangeState(grabbedState);
}

public void OnGrabExited() => stateMachine.ChangeState(putDownState);

04

VR 상호작용 오브젝트 — 성공은 버튼이 아니라 조건으로

각 오브젝트의 “성공”을 버튼 입력이 아닌 물리 · 각도 · 거리 · 시간 조건으로 판정했습니다.

오브젝트판정 방식구현 포인트
젠가블록이 타워 영역(트리거)을 완전히 벗어나면 성공 카운트, 실패 영역에 블록이 닿으면 게임 오버OnTriggerExit로 추출 판정 · 목표 개수 달성 시 이벤트 · 리셋 시 블록 상태와 카운트 초기화
카드Fisher–Yates 셔플 후 N장 × M묶음 분배묶음 전체 폭을 계산해 테이블 중앙 기준으로 정렬 · 원본 덱 목록을 백업해 분배한 카드 회수
설거지수세미와 닿아 있는 시간을 누적해 2초가 되면 세척 완료 → 머티리얼 교체건조대 소켓의 Select 이벤트로 접시 수 집계(꺼내면 감소) → 5개가 되면 미션 완료
술병 기울기 90° 이상이면 액체 파티클, 파티클이 잔에 닿으면 채워짐5° 여유 각도로 경계 깜빡임 방지 · 잔 기울기 90° 이상 + 얼굴 25cm 이내면 마심 · 3잔이면 URP Volume(렌즈 왜곡 · 색수차)으로 10초 취기
TV리모컨 트리거(Activate) 입력 시 앞쪽으로 15m Raycast맞은 오브젝트에서 TVController를 찾아 전원 토글 · 화면 표시와 VideoPlayer 재생 제어
쓰레기던진 순간의 위치를 저장하고, 1초 이상 완전히 멈추면 판정휴지통 영역 안에 멈췄고 던진 거리가 기준 이상이면 성공 · 다시 잡으면 판정 초기화
샌드백글러브 충돌의 상대 속도 × 100 = 점수최소 충격 기준 · 0.5초 재판정 대기로 중복 판정 방지 · 1000점 이상이면 이벤트
총잡은 총의 트리거(Activate) 입력으로 발사총구 위치에 머즐 플래시 생성 후 0.5초 뒤 제거 · 발사음 · 이벤트

TEAM INTEGRATION

퀘스트 시스템과의 연결

각 오브젝트는 판정 결과만 알리고, 퀘스트 진행은 팀원이 설계한 ScriptableObject 기반 조건 · 이벤트 채널이 담당합니다. 덕분에 오브젝트 스크립트는 퀘스트 구현을 몰라도 됩니다.
