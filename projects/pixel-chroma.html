01

Steam의 만남과 Mirror의 통신을 연결

문제

빠른 매칭, 코드 참가, 공개 로비 검색, 친구 초대가 같은 방 정보와 접속 절차를 공유해야 했습니다.

구현

Steam Lobby에 방 메타데이터를 기록하고, 입장 콜백에서 HostAddress로 호스트 SteamID를 읽어 Mirror 클라이언트를 시작합니다. Mirror는 게임 상태를 동기화하고 FizzySteamworks는 Steam P2P 전송을 맡습니다.

결과

여러 참가 경로가 하나의 입장 콜백으로 합류합니다. Steam 계정·로비·초대 기능을 활용하고, 참여자 한 명이 호스트를 겸해 별도 전용 게임 서버의 운영 부담을 줄였습니다.

02

3초마다 조건을 완화하는 빠른 매칭

문제

가까운 지역과 같은 언어의 방을 우선하되, 조건이 너무 엄격해 대기가 길어지는 상황을 피해야 했습니다.

구현

Close → Default → Far → Worldwide 순서로 3초마다 검색 범위를 넓힙니다. 첫 두 단계는 같은 언어를 유지하고 이후 언어 조건을 해제합니다. 공개·대기 중·빈자리 조건은 유지하며 미설치 창작마당 맵을 제외합니다.

결과

후보 중 인원이 가장 많은 방을 선택하고, 네 단계를 소진하면 실패를 안내합니다. CancellationToken으로 검색을 취소하며 로비 목록은 5초 주기로 갱신하고 입장 실패 후 재검색합니다.

03

색칠은 입력으로, 닉네임은 한 번의 업로드로

문제

애니메이션이 바뀌거나 새 플레이어가 입장해도 색칠과 픽셀 닉네임을 동일하게 유지해야 했습니다.

구현

원본 스프라이트와 분리된 폼별 Color32 마스크를 모든 애니메이션 프레임이 공유합니다. 브러시·지우개·채우기의 입력을 보내 각 클라이언트가 재현하고, 늦은 입장에는 칠한 칸을 1,000개씩 나누어 전달합니다. 60×12 픽셀 닉네임은 편집 프리셋 3개와 메인 키를 분리해 저장하고 접속당 한 번 업로드합니다.

결과

프레임별 텍스처 복사를 피하고 폼 전환 후에도 색칠을 복원합니다. 닉네임 명부의 PNG를 새 플레이어 오브젝트와 채팅·킬로그·점수판에서 재사용해 씬·역할 전환마다 재업로드하지 않습니다.

04

쿨타임을 지켰는데 거부되던 발사 해결

문제

클라이언트가 1.5초 간격을 지켜 발사해도 네트워크 지연 편차로 서버 도착 간격이 짧아져 발사가 거부됐습니다.

구현

자동 사격과 거부 로그로 원인을 확인했습니다. 서버 허용 오차를 0.10초에서 0.25초로 조정하고, 다음 기준 시각을 max(도착 시각, 이전 기준 + 쿨타임)으로 보정했습니다. 탄약 회복도 서버와 클라이언트에서 같은 주기로 계산합니다.

결과

지연 편차에 의한 정상 발사 거부를 줄이며, 허용 오차를 연속 사용해 연사 속도가 빨라지는 상황을 막았습니다. 같은 판정 방식을 크로마 도발 쿨타임에도 적용했습니다.
